Manual installation

This walkthrough installs ByteOS to a raw disk image, then writes that image to a real disk. It is the same result as the guided installer, but every step is explicit.

Destructive. dd writes exactly where you point it. Double-check device names with lsblk before pressing Enter. One wrong letter can erase your main disk.

0. Checklist

  • Windows with PowerShell, or Linux/macOS with a shell.
  • NASM, LLVM/Clang, Python 3, and QEMU if you build from source.
  • A 64 MiB or larger raw disk image for the VM.
  • A spare USB stick or disk for the finished installation.
  • Firmware set to legacy BIOS/CSM boot, with legacy USB support enabled.
  • An IDE/PATA or AHCI SATA target disk (not RAID or NVMe), and a VGA-compatible display.

1. Get the source

git clone https://github.com/withdrawment/byteos
cd byteos

Or download a release ISO from GitHub releases and skip to step 3.

2. Build the ISO

On Windows:

.\build.ps1

This produces ByteOS.iso, build\boot.bin, build\kernel.bin, build\mbr.bin, and the hybrid USB MBR in build\usbmbr.bin. The build uses the project's own ISO writer; no external ISO tool is required.

3. Create the target disk image

64 MiB is plenty for ByteOS and its website:

qemu-img create -f raw byteos-disk.img 64M

On Windows, if qemu-img is not on PATH, use the copy in the QEMU installation folder.

4. Boot the live ISO with the target disk

qemu-system-x86_64 -m 1024 -smp 4 \
  -cdrom ByteOS.iso \
  -drive file=byteos-disk.img,format=raw,if=ide \
  -boot d
  • -cdrom is the live ISO.
  • -drive ...,if=ide makes the target disk visible to the PIO driver on the default machine and to the AHCI driver with -machine q35.
  • -boot d boots the CD first.

5. Install from the live console

At the byteos> prompt:

byte-install

Answer the prompts. A typical session:

Installation disk [1-1]: 1
Username: byte
Password: ****
Repeat password: ****
Root password: ****
Repeat root password: ****
Hostname [byteos]: byteos
Type INSTALL to erase the disk: INSTALL

The installer writes, in order:

  1. the MBR at LBA 0, with one active partition at LBA 2048;
  2. stage 2 at LBA 1;
  3. the flat kernel at LBA 66;
  4. a formatted ByteFS partition at LBA 2048;
  5. the offline website, README, sample pages, and your account database.

When it finishes, press R to reboot, or any other key to stay in the live shell.

6. Boot the installed disk image

qemu-system-x86_64 -m 1024 -smp 4 \
  -drive file=byteos-disk.img,format=raw,if=ide \
  -boot c

You should see the ByteOS login screen. Sign in with the user you created. Run fetch, start-desktop, and open the browser's www/index.html to confirm everything is on disk.

7. Write the image to a real disk (optional)

Linux/macOS:

lsblk
sudo dd if=byteos-disk.img of=/dev/sdX bs=4M status=progress conv=fsync

Replace /dev/sdX with the whole target device. Do not append a partition number. On macOS use /dev/rdiskN.

Windows: use Rufus in DD mode, or balenaEtcher, and select byteos-disk.img as the source.

Then boot the target machine in legacy BIOS/CSM mode. If the firmware offers a boot order, put the target disk first.

8. Alternative: install directly to the real disk

If the target disk is visible to your firmware as an IDE/PATA or AHCI SATA disk, you can boot the hybrid USB ISO on the real machine and run byte-install directly, selecting that disk. This avoids the image-copy step. It is still destructive: check the model and size shown by the installer before confirming.

9. Verify the installation

fetch
ls
cat README.TXT
start-desktop

In the browser, open www/index.html and www/manual.html. In Files, select home/notes.html and press F4, make a small edit, and save with Ctrl+S. Reboot and confirm the edit survived.

Manual layout reference

LBA 0        MBR and partition table
LBA 1..65    stage 2
LBA 66..     kernel
LBA 2048..   ByteFS partition (MBR type 0x42)

ByteFS sector 0..3     superblock and directory
ByteFS sector 8..      file contents

The supported way to create this layout is byte-install or this guide. Hand-writing sectors is possible but offers no advantage over the installer.

Troubleshooting

  • No disks in the installer: attach the disk with if=ide, or set the SATA controller to AHCI/IDE rather than RAID on the machine. NVMe is not supported.
  • No keyboard input: use a PS/2 keyboard or enable legacy USB support. The kernel polls the 8042 controller; it has no USB stack.
  • QEMU boots the ISO again: use -boot c and omit -cdrom when booting the installed disk.
  • Login fails: usernames are case-insensitive; passwords are not. Reinstall if the password is lost.
  • No HTML page in the browser: type u and enter www/index.html, or run ls to confirm the files were installed.
