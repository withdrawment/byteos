ByteOS documentation

Everything you need to boot, explore, install, and rebuild ByteOS 0.2.

Commands are case-insensitive. Aliases: dir for ls, sysinfo for specs, cls for clear, ? for help. The shell keeps a virtual current directory over the flat ByteFS namespace; paths such as www/docs.html imply their parent directories.

Desktops

Run start-desktop from the console and pick a desktop. The chooser runs every time; start-desktop classic, start-desktop win95 and start-desktop tile start one directly.

ByteDesktop

The classic 80x25 text-mode desktop. Use the arrow keys to pick an app and Enter to open it. F10 or Esc returns to the desktop; the desktop itself returns to the console when you choose Exit.

  • Files - browse ByteFS. Enter opens HTML in the browser; F4 opens it in the editor.
  • Browser - local HTML reader. Type a path with u, follow numbered links, Backspace goes back, and e edits the current page.
  • Editor - HTML-only editor. Ctrl+S or F2 saves to ByteFS, Esc leaves.
  • Terminal - the full ByteOS shell inside the desktop. Type exit to return.
  • Fetch - the same system summary as the console command.

ByteWin 95

A genuine 640x480 VGA mode 12h desktop with 16 colours, a mouse cursor, icons, and overlapping windows. It saves and restores the text-mode VGA state, so the shell comes back exactly when you leave. A 16-pixel SSE2 planar converter and span-only presentation keep the pointer and window dragging smooth.

  • Start menu - click Start or press F10. It opens My Computer, Notepad, Command Prompt, System Properties, About ByteWin 95, the original TUI apps, a native Fetch window, Fetch (TUI), Donut, Screensaver, Restart, and Shut Down.
  • Windows - drag title bars, click taskbar buttons, double-click icons and files, and use the minimize, maximize/restore and close boxes. Double-clicking a title bar also toggles maximize. Clicking the focused window's taskbar button minimizes it.
  • My Computer - browses ByteFS on an installed disk, or the built-in ISO pages when running live.
  • Fetch - a native ByteWin window with a large colour torus and live system data. The graphical fetch command opens it; the full-screen version remains as Fetch (TUI).
  • Screensaver - a colour starfield warp starts after 60 seconds without input, or on demand from Start > Screensaver. Any key or mouse movement returns to the desktop.
  • Command Prompt - a graphical shell with ls/dir, cd, pwd, mkdir, rmdir, touch, rm, cat, lsblk, df, free, uname, date, uptime, hostname, echo, whoami, clear, exit, fetch, history, and help. Up and Down recall previous commands.
  • TUI handoff - Browser, HTML Editor, Terminal, Fetch (TUI), and Donut switch to text mode, run the original app, then return to the GUI.

F10 opens Start, F12 leaves ByteWin 95, Esc closes the focused window, Tab cycles visible windows, and Enter launches the selected icon or menu item. F12 and Shut Down return to the shell; Restart reboots the machine.

ByteTile

A keyboard-only, dwm-style tiling window manager in the same 640x480 VGA mode 12h, with nine tags. Windows are arranged automatically and never float. ByteTile starts with one terminal and shows a key reference whenever the current tag has no windows.

  • Tags - Alt+1..Alt+9 view a tag; Alt+Shift+1..Alt+Shift+9 move the focused window to a tag.
  • Layouts - Alt+Space cycles tile, monocle and grid. Alt+h and Alt+l resize the master area; Alt+f toggles zoom.
  • Focus - Alt+j and Alt+k cycle windows; Alt+Shift+j and Alt+Shift+k move a window in the stack.
  • Windows - Super+Return opens a terminal, Super+Space opens the launcher, and Super+Q closes the focused window. Super is the Windows or Command key; Alt+Return, Alt+p and Alt+q are aliases.
  • Clients - Terminal, Browser, Files, System monitor, Viewer, Config editor and Key reference. Files opens HTML pages in the browser, and the terminal supports the shell command set: ls/dir, cd, pwd, cat/type, mkdir, rmdir, touch, rm, cp, mv, head, tail, wc, grep, less/more, date, time, uptime, whoami, id, hostname, uname, free, df, lsblk, env, ps, top, open, browse, edit, keys, tags, history, echo, fetch, specs, memmap, about, version, tileconf, reboot, clear/cls, help/man and exit.
  • Browser - a native graphics client for the bundled site and ByteFS pages. Press 1-9 to follow a link, b or Backspace to go back, r to reload, u to type an address, h for the home page, and the arrow, PgUp/PgDn, Home and End keys to scroll. Esc closes it.
  • Config - Alt+Shift+C opens /bytetile.conf; Ctrl+S saves and applies, Ctrl+R reloads. On a live ISO changes live in RAM; an installed system writes them to ByteFS and restores them after a reboot. tileconf prints the file from the shell.

Disk layout

LBA 0          MBR (ByteOS stage 1)
LBA 1..65      stage 2 + page-table setup
LBA 66..       flat kernel
LBA 2048..     ByteFS partition (type 0x42)

ByteFS:
  sector 0..3    superblock + 32 directory entries
  sector 8..     contiguous file data

ByteFS stores full paths such as www/index.html and etc/passwd. It is intentionally simple: no journal and no permissions. Directories are virtual: a path implies its parent directory, and mkdir adds an explicit directory entry. Account passwords are stored as FNV-1a hashes, which is appropriate for a demo OS but not production security.

Boot path

  1. The ISO's El Torito catalog loads the full boot image at 0x7C00. The hybrid USB MBR loads the same image from the ISO layout when the stick is booted as a hard disk.
  2. On an installed disk, the ByteOS MBR loads stage 2 from LBA 1, then stage 2 reads the kernel from LBA 66.
  3. Stage 2 initialises COM1 diagnostics, checks CPUID and long mode, enables and tests A20 with a BIOS fallback, gathers the E820 map, sets VGA text mode, builds identity-mapped 2 MiB pages, and enters long mode.
  4. The kernel clears BSS, probes VGA and the keyboard, detects the CPU, calibrates the TSC (PIT with a CPUID 0x15/0x16 fallback), probes PIO and AHCI disks, mounts ByteFS when booted from disk, shows the login screen, and starts the shell.

Limitations

  • Legacy BIOS / CSM only. Native UEFI and Secure Boot are not implemented.
  • ATA PIO and AHCI SATA disks are supported. NVMe, RAID-mode SATA, and USB mass storage are not driven by the kernel; USB sticks work as firmware-emulated boot media.
  • VGA-compatible output only: text mode 80x25 and mode 12h at 640x480 with 16 colours. There is no VBE framebuffer.
  • No networking. The browser reads local files; external links show their URL.
  • One task, ring 0 only. ByteWin 95 and ByteTile are single-threaded 640x480 GUIs, and the classic desktop is 80x25 text mode.
  • Installation erases the selected disk. Use a spare disk or QEMU image.

Build from source

git clone https://github.com/withdrawment/byteos
cd byteos
.\build.ps1
.\run.ps1

On Windows the build needs NASM, LLVM/Clang, Python 3, and QEMU for run.ps1. See the repository README for details.
