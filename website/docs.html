ByteOS documentation

Everything you need to boot, explore, install, and rebuild ByteOS 0.2.

Console commands

CommandWhat it does
helpShow the command list.
fetchFastfetch-style system summary and ASCII art.
specsFull CPUID, memory, firmware, timer, and RTC report.
memmapRaw BIOS E820 memory map.
aboutProject background.
donutSpinning z-buffered ASCII donut. Any key returns.
start-desktopLaunch ByteDesktop.
byte-installGuided installer for an ATA/IDE disk.
lsList files on the installed ByteFS disk.
cat FILEPrint a text file from ByteFS.
whoamiShow the signed-in account.
suSwitch to root with the root password.
passwdChange the current account password.
logoRedraw the boot screen.
clearClear the console.
rebootWarm reboot.

Commands are case-insensitive. Aliases: sysinfo for specs, cls for clear, ? for help.

ByteDesktop

Run start-desktop from the console. Use the arrow keys to pick an app and Enter to open it. F10 or Esc returns to the desktop; the desktop itself returns to the console when you choose Exit.

  • Files - browse ByteFS. Enter opens HTML in the browser; F4 opens it in the editor.
  • Browser - local HTML reader. Type a path with u, follow numbered links, Backspace goes back, and e edits the current page.
  • Editor - HTML-only editor. Ctrl+S or F2 saves to ByteFS, Esc leaves.
  • Terminal - the full ByteOS shell inside the desktop. Type exit to return.
  • Fetch - the same system summary as the console command.

Disk layout

LBA 0          MBR (ByteOS stage 1)
LBA 1..65      stage 2 + page-table setup
LBA 66..       flat kernel
LBA 2048..     ByteFS partition (type 0x42)

ByteFS:
  sector 0..3    superblock + 32 directory entries
  sector 8..     contiguous file data

ByteFS stores full paths such as www/index.html and etc/passwd. It is intentionally simple: no journal, no permissions, no directories on disk. Account passwords are stored as FNV-1a hashes, which is appropriate for a demo OS but not production security.

Boot path

  1. The ISO's El Torito catalog loads the full boot image at 0x7C00.
  2. On a hard disk, the ByteOS MBR loads stage 2 from LBA 1, then stage 2 reads the kernel from LBA 66.
  3. Stage 2 enables A20, gathers the E820 map, sets VGA text mode, builds identity-mapped 2 MiB pages, and enters long mode.
  4. The kernel clears BSS, detects the CPU, calibrates the TSC, probes ATA, mounts ByteFS when booted from disk, shows the login screen, and starts the shell.

Limitations

  • Legacy BIOS / CSM only. Native UEFI is not implemented.
  • ATA PIO (IDE) disks only. AHCI, NVMe, and USB storage are not supported.
  • No networking. The browser reads local files; external links show their URL.
  • Text mode 80x25, one task, ring 0 only.
  • Installation erases the selected disk. Use a spare disk or QEMU image.

Build from source

git clone https://github.com/withdrawment/byteos
cd byteos
.\build.ps1
.\run.ps1

On Windows the build needs NASM, LLVM/Clang, Python 3, and QEMU for run.ps1. See the repository README for details.
